## Lessons

- After a toolchain pin bump in `native/toolchain.json`, existing `artifacts/native/*/CMakeCache.txt` files retain absolute paths to the prior MSVC linker (`CMAKE_LINKER`); cleaning `artifacts/native/` (while keeping `artifacts/vcpkg_installed/`) clears stale toolset caches immediately.
- Under `three-pass`, `astra` runs in a proxy-restricted sandbox without live GitHub API access, so post-push CI run IDs, artifact download checks, and `ci_watch.py` outputs required by a `Test checkpoint` must be committed or supplied via `--gates` before `completion` / `reconciliation`.
- After any edit to a TODO file, run `plan --sync` before quoting `plan --check`: the ignored operator projection goes stale on a text-only edit, and a reviewer running the check in the same tree sees it fail.
- A superseded push cancels the `build` run before it; read CI back on the newest head over the whole range, and treat `cancelled` as unread, not red.
- Write item evidence as `Done <date>: ...` and corrections as ` **Corrected <date>** ...` at the end of the line: the stamp reads everything else on an item line as the section's promise.
- Run Pass 1 (the plan review) on the commit that holds only `Started:` and the plan corrections, before building.
- A section the re-plan keeps but reopens needs three things written before its plan review, not after: a `Started:` line for the new interval (the old one in a dated note), one `Commit:` item only, and its evidence in the neutral `Done <date>:` form. `D00 T01 §5` and `D00 T03 §1` and `§2` get them at their start.
- When a reviewer finds one unvalidated edge between two inputs, look for the rule that covers the class before patching the instance: `D00 T01 §8` patched one route check after the round, and the completion pass found two more of the same kind that one catalog-level pass over the related file closed together.
- A chained shell line whose first step fails must not reach `git push`: join the commit and the push with `&&`, never `;`.
- While a build runs on GitHub, build and review the next section locally and hold its push until that build reports: a push cancels the run before it, and the stamp needs that run.
- Quote every command a Test checkpoint names in the section before the completion pass, `validate` included, with its exit code and summary.
- A check that reads a file a run wrote must refuse what is absent as well as what is wrong: `--verify` first passed a manifest entry with no picture, because it only judged the fields it found.
- A tool that reproduces another tool's output reuses that tool's rules, not a likeness of them: the reference renderer had its own padding and width rules, and two components had been rendering wrong for as long as nobody checked the pictures.
- Send long-running Python output through `python -u` when it is redirected to a log, or a hung run and a slow one look the same.
- Run the last review pass before the last push: the reconciliation of `D00 T01 §9` ran locally on the fix commit, so one CI run covered the final commit instead of two.
- When a gate's trigger is widened, run every consumer of the old trigger before pushing: `merge_prs.py` read the path filter `D00 T01 §10` removed, and its fixtures went red in CI.
- A probe of a review lens needs a real stale text and a real correction, judged by the pinned reviewer: the first probe showed the lens finding everything and rating it non-blocking, which no amount of skill text would have shown.
- When a check binds a fact to its owner, keep the check on the consumer that acts on the fact: binding the release comment to its app dropped the check on the trigger itself.
