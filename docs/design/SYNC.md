## Publishing a change from the repository

1. Commit the change in `docs/design/` first; the artifact never runs ahead of `main`.
2. Read the artifact's live version (Artifact tool, action `list` with `scope: "files"`, then `read` of any file you are about to replace) so the publish builds on what is there.
3. Publish with the Artifact tool: `url` set to the artifact, `root` set to `docs/design`, and a `files` map from each published path to its repository source, for example `{"project/tokens.json": "tokens.json", "project/components/Menu/README.md": "components/Menu/README.md"}`. Send only the files that changed; files left out are kept.
4. Publish `project/design-system.json` last (in the final call when a change needs more than one), after updating its `lastChange` to `{"by": "<name>", "at": "<UTC time>", "via": "repo", "note": "<what changed>"}`. Keep `createdOnFiles` exactly as it is: it records when the system moved to the files layout.
5. Never publish the generated paths or the type's files listed above; the page regenerates `tokens.css`, `api/` and `manifest.json` from what you publish.

## Pulling an edit made on the artifact page

If anyone edits the system on the artifact page, the repository is behind and must catch up before any repository edit:

1. `list` the artifact's files and compare the version against the one named at the top of this file (or the last `lastChange` in `design-system.json`).
2. `read` the changed `project/` files with `paths` (batch), skipping the generated and type files.
3. Diff each against `docs/design/`, copy the artifact's version in, and commit it on its own ("docs(design): pull artifact edits of <date>"), noting the artifact version in the body and updating the version line above.
4. Only then make the repository edit and republish as above.

## App icons

The fifteen app icon SVGs live in `resources/icons/<app>/` (`<app>.svg`, `<app>-16.svg`, `<app>-24.svg`, `<app>-32.svg`, `<app>-splash.svg` for `nodus`, `imago`, `lumen`) and are not copied into `docs/design/`. On the artifact they are the "App icons" asset group; `design-system.json` lists each file's blob id, and `components/AppIcon/preview.html` references those ids as `/_blob/<id>`.

When an icon changes in `resources/icons/`, upload it to the artifact's asset store (publish with `url`, `asset: true`, `file_paths`), then update the file's `blob` and `size` in `design-system.json` and every `/_blob/<id>` reference in `components/AppIcon/preview.html` to the new id, commit, and publish those two files.

At import the artifact blobs matched the repository files in content; they differ only in serialization (the artifact writes `<stop ...></stop>` where the repository writes `<stop .../>`), so their byte sizes differ from the repository's.

## Checks

- `docs/design/tokens.json` and `docs/design/design-system.json` must parse as JSON.
- The WPF theme dictionaries in `src/Photon.UI/Themes/` are generated from `tokens.json` (`D01 T01 §3`); a token change regenerates them in the same commit, and the drift check fails when they disagree.
