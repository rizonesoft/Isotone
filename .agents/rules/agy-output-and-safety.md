# Antigravity Output, Runtime, and Autonomy Rule

- Bound every shell command output (`Select-Object -First` on Windows, `head` or `tail` on Git Bash, filtered test cases) and redirect full logs to scratch, never a tracked path: in Isotone that is the ignored `build/` (`AGENTS.md` "Output discipline"; subagent logs go under `build/delegation/`).
- Treat `git status` as a concurrency lock: never write over unfamiliar uncommitted changes from another session without asking the user first.
- Never use em dashes or en dashes anywhere: prose, code, comments, commit messages, and generated files. Use `--`, a comma, a colon, parentheses, or a full stop. Write one line per Markdown paragraph and list item.
- Use atomic temporary-file-then-replace writes for all persistent data files.
- Author and execute TODO work as small, single-responsibility sections with granular micro-step checklist items (`Done when:` and backticked path or symbol per item) toward a 100% complete development plan with zero silent drops or unowned controls.
- End code change reports with a `Layer:` line identifying the owning module, and format every file and code symbol reference in user responses as a clickable `file://` Markdown link using forward slashes and basename link text.
- Antigravity runtime mappings when executing skills under `.agents/skills/` (mirrored in `.claude/skills/`): build prompts through `scripts/review-prompt.py`, pass `--writer agy` to `scripts/review-dispatch.py`, and stamp sections through `scripts/todo-graph.py stamp`; pass the session's `Conversation ID` from `<user_information>` to `scripts/campaign_guard.py --session <conversation-id>`; replace `CronCreate`, `CronList`, and `CronDelete` with Antigravity's `schedule` (`CronExpression: "*/13 * * * *"`) and `manage_task` (`list` and `kill`) tools; and use `invoke_subagent` with `TypeName: "research"` on `inherit` (`define_subagent`, `self`, `swarm` workers, `pro`/`flash`/`flash_lite` overrides, and headless CLI agent runs are denied) so subagents read and never write (`standards/delegation.md`).
- Act autonomously, self-improve, and self-heal (`AGENTS.md`, "The writer acts on its own judgment, and improves and repairs its own work and tools"): work out technical, design, and planning answers from the source, specifications, measurements, and driven runs, record decisions with their cost of changing, and never stop to ask questions you can answer yourself. Ask the operator only for credentials, money spent, legal or trademark decisions, or destructive external actions.
- Self-improve and self-heal continuously: when a measurement shows the repository's runners, skills, gates, toolchain, or methods cost time, memory, or quality, file and build the improvement through `add-todo` with a checkpoint; when a gate, hook, runner, pin, scheduled task, or build tree breaks, diagnose and repair it at its owning layer in the same run.
- Always develop straight on `main`: never create feature branches (`git checkout -b`, `git switch -c`, `git branch <name>`) or secondary git worktrees (`git worktree add`).
- Use the `isotone-lsp` MCP tools (`lsp_diagnostics`, `lsp_hover`, `lsp_definition`, `lsp_references`, `lsp_document_symbols`, `lsp_workspace_symbols`, `lsp_status`) from `.agents/plugins/isotone-lsp/` (`scripts/lsp-mcp-server.py`) for C/C++ (`clangd` + `clang-tidy`) and Python (`pyright`) symbol resolution and diagnostics instead of text-grep guessing.
- Never block an unattended campaign (`ISOTONE_CAMPAIGN_UNATTENDED=1` or an active `build/claude-campaign-guard.json`) on interactive UI prompts: `ask_question` and `ArtifactMetadata.RequestFeedback=true` are mechanically denied during unattended runs.
- Aim past every competitor regardless of size (Adobe, Microsoft, Apple, or Google): never take shortcuts or workarounds, never scope a feature or `**Exceed:**` target down because it is difficult or complicated, and break any seemingly impossible problem into concrete, verifiable steps until the result blows the competition away.
