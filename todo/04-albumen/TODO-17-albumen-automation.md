# TODO-17 -- Albumen Automation: Recorded Actions, Extensions, and the Command Line

> **Goal:** Albumen takes part in the suite's one automation system (`D01 T10`) the way ACDSee, Lightroom Classic, and IrfanView users expect: edits are recorded as actions and played back on other photos from the Actions menu, the viewer's Actions Browser, and batch export; extensions add metadata fields, export destinations and filters, publish services, library filters, external tools, and menus through the suite extension SDK, managed from one extension manager; and every IrfanView command-line switch and ACDSee's catalog switch drives Albumen and the Albumen Viewer through the suite command-line parser. Originals stay safe by default with opt-in writes (operator decision 2026-09-27, "Safe by default, opt-in writes"): playback, extensions, and the command line write new files unless the user turned on the matching `Albumen.Originals.InPlace.*` opt-in, and never behind its back.

## 1. Recorded Actions in Albumen

ACDSee records a series of edits and plays it on other images from its Actions Browser, and applies an action as a step of a batch export. Albumen does the same on the suite action model: every Albumen command that changes a photo is recordable with its parameters, the Actions panel of `D01 T10 §2` is hosted as the Actions Browser in the viewer and the main window, and `ActionBatchOperation` joins batch export. ACDSee's actions "play back destructively" (LP-1223); in Albumen a playback writes new files or catalog edits by default and replaces an original only when the user turned on the matching `Albumen.Originals.InPlace.*` opt-in (operator decision 2026-09-27, "Safe by default, opt-in writes"), which the Actions Browser says.
