# TODO-10 -- Albumen AI: Faces, Keywords, Similarity, Culling, and Masks

> **Goal:** Albumen's AI answers every Lightroom Classic and ACDSee AI job on the suite's three pillars. Results are editable, structured, non-destructive data applied as undoable catalog or edit-stack commands: a suggested keyword, caption, detected face, verdict, or setting is a proposal the user accepts, an AI mask is a develop mask component, generative removal is a develop spot, and enhanced pixels are new files. The features are suite-aware: they run on the shared AI core `D01 T05` (OpenRouter with the user's own key stored with DPAPI, the explicit-send gate and send preview, provenance), and the segmentation engine, vision locator, image-generation adapter, distraction finder, and depth estimator Pinxit built move to `Isotone.Core` on this second consumer. Every action is explainable and reproducible: the prompt, model, parameters, and seed (with whether the model honored it) are recorded in the catalog, shown in the photo's history, re-runnable and comparable, and embedded as XMP in exports. Similarity is local perceptual hashing; face detection, keywords, captions, alt text, OCR, eye-state culling, mask locating, auto settings, super resolution, and generative removal send a downscaled, metadata-stripped copy only after an explicit action and the send preview (face detection through an OpenRouter vision model by the operator's decision of 2026-09-27, which did not approve local face models for Albumen); faces are named by hand, and recognizing the same person across photos is backlog B-052; denoise is classical by default, with optional on-device models for denoise, raw details, keywords, and similarity in §13 (ONNX Runtime through `D01 T12`, nothing leaving the machine). Code lives in `src/Albumen/Isotone.Albumen.Core/AI/` and `src/Albumen/Isotone.Albumen.Core/Faces/`, with shared pieces in `src/Isotone.Core/AI/` and `src/Isotone.Core/Imaging/Segmentation/`. Every test runs over the recorded transport of `D01 T05 §1`; no live key is used in CI.

## Outcome

- Every Lightroom Classic and ACDSee AI job in the catalog maps to a Albumen feature reachable from one AI menu, each wired or disabled with its owner section named.
- No request reaches OpenRouter without an explicit user action and a send preview whose listed bytes are the request body; outgoing images are at most `Albumen.AI.MaxEdge` pixels on the long edge with metadata stripped, proven over the recorded transport.
- Faces are detected through the vision model only after an explicit send with the send preview or under an approved send scope, each run recorded with provenance, and named by hand; a detection request carries only the downscaled, metadata-stripped photo, never a face crop or a name.

- Every AI action writes a provenance record into the catalog with prompt, model, parameters, seed, whether the seed was honored, hashes, and cost, shown in the photo's history, re-runnable and comparable, and embedded as XMP in exports.
- Pinxit's segmentation engine, vision locator, image-generation adapter, upscale service, distraction finder, and depth estimator live once in `Isotone.Core`.
- Denoise, raw details, keywords, and similarity can run offline on downloaded models whose licenses are recorded, chosen per task in the Model Manager, with the same provenance and nothing sent (§13).
