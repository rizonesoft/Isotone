# TODO-11 -- Photon.Core Media: Decoding, Playback, Audio, and Encoding for Video and Sound

> **Goal:** The suite reads, plays, and writes video and sound through one media layer in `src/Photon.Core/Media/` and one transport control in `src/Photon.UI/Media/`, so Imago's video layers, timeline, and Render Video (`D03 T23`) and Lumen's video cataloging, playback, trimming, Media mode, image audio, and video slideshows (`D04 T16`) never grow two decoders, two clocks, or two playbars. Windows Media Foundation through Vortice.MediaFoundation decodes, encodes, and plays; XAudio2 through Vortice.XAudio2 mixes audio; an optional FFmpeg the user installs is run as an external process for the containers and codecs Media Foundation lacks, never bundled and never linked. Every decode is frame-exact against a named reference, every encode writes a new file atomically, and no media operation ever writes a source file. This file exists because the operator promoted the video and audio work deferred to after the first release (operator decision 2026-09-27, planned so no feature is "left behind").

> [!IMPORTANT]
> **Current state (verified 2026-09-27):** There is no `src/Photon.Core/` or `src/Photon.UI/` yet (`D01 T02 §1` and `D01 T01 §1` create them) and no Lumen source tree. No source file under `src/` references Media Foundation, XAudio2, or FFmpeg, and `Directory.Packages.props` has no Vortice package: Vortice.Windows arrives with Imago's HDR display (`D03 T15 §4`) and Lumen's quick-slideshow music (`D04 T04 §8`, `SlideshowAudioPlayer` in `src/Lumen/Photon.Lumen.Core/Audio/` over the Media Engine), which is the first media code the plan builds and the one §1 moves here on its second consumer. The shared codec registry (`D04 T13 §1`) reads still images only; animated GIF, APNG, WebP, MNG, and FLI playback in the viewer (`D04 T04 §10`) are frame sequences, not media sources.

## Outcome

- `IMediaSource` opens every video and audio format in `MediaFormatRegistry` and decodes any frame at a timestamp within 2/255 of FFmpeg's rawvideo output for the same frame; formats Media Foundation cannot read open through a user-installed FFmpeg or are refused by name.
- `MediaPlayer` plays video and mixed audio in sync within one frame, with loop, rate, seek, and frame step, and audio CDs and MIDI play through Windows.
- `MediaEncoder` writes MP4 (H.264 and AAC), HEVC where the Windows extension exists, WMV, WAV, and image sequences to new files atomically, and a decode of each written file matches its frame count, duration, and a stated PSNR.
- One MediaTransport control in `Photon.UI` is the playbar every app shows, drawn from its design spec.
- No media operation opens a source file for writing, and FFmpeg is never shipped in an installer.

## 1. The Media Stack Decision and Decoding

Imago's video layers and Lumen's video library both need to open a clip, read its streams, and pull an exact frame at a timestamp, and a second decoder in either app would be a defect. This section records the media stack decision and builds decoding once. Windows Media Foundation, reached through Vortice.MediaFoundation (MIT, part of Vortice.Windows, approved by the operator 2026-09-27), is the primary backend: it ships with Windows, decodes H.264, HEVC (with the Store extension), VP9 and AV1 (with their extensions), MPEG-2, MJPEG, WMV, AAC, MP3, FLAC, ALAC, and WAV, and costs no bundled codec. FFmpeg is optional: the user installs it, Photon runs `ffmpeg.exe` and `ffprobe.exe` as external processes located by `Photon.Media.FfmpegPath` or `PATH`, and never bundles or links it. Running a separate program is not linking, so either an LGPL or a GPL FFmpeg build is compatible with Photon's GPL-3.0, and not shipping it keeps patent-encumbered codecs and FFmpeg's own license obligations out of Photon's installers. FFmpeg covers only what the installed Media Foundation cannot read (FLV, and MKV, WebM, TS, MTS, 3GP, Video CD DAT, RealAudio, and module audio where the codec is missing); those formats are disabled with a message naming FFmpeg when it is absent, the pattern Ghostscript follows in `D02 T14 §9` and `D04 T13 §4`. Lumen's `SlideshowAudioPlayer` (`D04 T04 §8`) is the first Media Foundation code in the plan, so its plumbing moves here on this second consumer. Catalog: none of its own (the rows are owned by `D03 T23` and `D04 T16`, which consume this section). -> SOURCE: parity-imago-video
