# TODO-21 -- Gesso Parity Releases: 0.2.0 to 1.0.0

> **Goal:** Each Gesso parity phase ends with a published, independently installable Gesso release on its own `gesso-v*` tag, proven on a clean machine, whose release notes list the parity catalog features the phase completed, so progress is shipped rather than accumulated; `gesso-v1.0.0` at the end of Phase 27 declares the catalog complete (every `plan` row stamped, every other row carrying its recorded status); `gesso-v1.1.0` to `gesso-v1.3.0` (Phases 42 to 44) ship the work the operator planned on 2026-09-27 from the entries deferred after the first release: suite automation, video and animation, and on-device models with the GPU develop path.

> [!IMPORTANT]
> **Current state (verified 2026-09-26):** Gesso's only planned release so far is 0.1.0 (`D03 T06 §3`, `todo/03-gesso/TODO-06-gesso-release.md`), which has not shipped: no `gesso-v*` tag exists and `CHANGELOG.md` has no Gesso release section. **Adjacency rationale:** The release notes in `CHANGELOG.md` and the user-guide pages are the documents each release carries. Each release quotes the per-phase parity report that `D00 T01 §7` builds. The tag, the release notes, and the stamped rows are the audit trail of what each version shipped. The reverse of a release is the gate itself: a failed clean-machine install or an unreconciled catalog row blocks the tag, and the previous release stays current; a bad release is superseded by the next patch tag, never deleted.

## 1. Gesso 0.2.0 (Phase 16)

`gesso-v0.2.0` releases Phase 16 (document, canvas, view, history, and layers), so the phase's parity work reaches users as an installable release rather than accumulating on `main`. It follows the checklist in `standards/release.md` exactly, as `D03 T06 §3` did for 0.1.0, quoting each line's evidence, and it adds three parity duties: the phase's catalog rows in `docs/parity/gesso-parity.md` are reconciled against their sections' stamps with `query parity --catalog gesso` (from `D00 T01 §7`), no Gesso menu item is disabled without naming a planned section or a backlog id (the audit `D03 T06 §2` established), and a document saved by this release is opened in the previous release, `gesso-v0.1.0` (`D03 T06 §3`), to prove its new live content degrades to the rendered PNG fallback of the `D03 T08 §1` contract instead of being lost. A catalog row that cannot ship is rerouted in `docs/parity/gesso-parity.md` in this commit (to a later section, or to the backlog through `add-todo`) with its reason, never left planned and unshipped. The clean machine is Windows 11 (the supported OS); a Windows 10 22H2 smoke is best-effort and recorded, never blocking. No other app's version moves with this tag (`standards/release.md`). The admission clause is the acceptance-bar aim "Gesso covers every Photoshop, Affinity Photo, and GIMP capability in its parity catalog", which names each release as the reconciliation of its phase. The release owns no catalog rows of its own: it reconciles the rows of the areas Documents and canvas; View, guides, and measurement; History, clipboard, and the Image menu; Layers and the Layers panel; Masks, clipping, and blending.

**Fidelity:** no surface of its own (the release artifacts are the installer, the portable ZIP, the release notes, and the tag; each surface was captured by the section that built it).

**Needs:** Clean Windows machine (no .NET SDK)

**Requires:** display-session -- launching the installed app on the clean machine and driving each new surface needs an interactive desktop
