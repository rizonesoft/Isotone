## 3. The Native Advisory Job

Libraries are linked statically, so a vulnerable library is fixed only by rebuilding and releasing every app that links it, and that starts with knowing (spec, "Dependencies and their upkeep"). The job must fail rather than report clean on a library it cannot check, and it must be proved against a known vulnerable version.

- [ ] Write `scripts/check-native-advisories.py` (stdlib Python): for each register row, query OSV with its advisory identity (`osv-git`: a Git-ecosystem query for the upstream repository at the released tag, following `next_page_token` until the response carries none, any page's failure counting as `unchecked`; `feed`: fetch the feed and match the version against each entry), report every advisory affecting the registered version as `library version advisory-id summary`, and exit 1 on any finding, on a row with no identity (`unmapped`), and on a failed or unparseable query (`unchecked`); a registry helper row, whose identity is exactly `none: build-time helper, not linked` and which `native-deps-lint` has validated as a helper that nothing links (§1), is not queried and is reported as `helper`, never `unmapped`; `--json` prints the same as JSON.
