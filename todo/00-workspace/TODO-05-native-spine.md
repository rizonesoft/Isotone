## 3. The CMake Build, Presets, and the Test Harness

The build description is CMake with Ninja and committed presets that Visual Studio also opens (spec, "Build description"). C++23 comes from an explicit `/std:c++23preview`, because CMake turns `CXX_STANDARD 23` into `/std:c++latest` on MSVC, which the standard decision forbids. The first library and test are deliberately trivial: they prove the build, not a feature. Every `cmake`, `ctest`, and `vcpkg` command in this file runs inside `scripts/dev-env.ps1` with `native/` as its working directory, because the presets live there (CMake looks for `CMakePresets.json` in the current directory): `scripts/dev-env.ps1 -Run` takes `-WorkingDirectory`, defaulting to `native/`, and scripts that call CMake from elsewhere `Push-Location native` first.

- [ ] Write `native/CMakeLists.txt`: `cmake_minimum_required` at the pinned CMake's major and minor, `project(Isotone LANGUAGES C CXX)`, `CMAKE_CXX_STANDARD 23` with `CMAKE_CXX_STANDARD_REQUIRED ON` and `CMAKE_CXX_EXTENSIONS OFF`, and `CMAKE_CXX23_STANDARD_COMPILE_OPTION` and `CMAKE_CXX23_EXTENSION_COMPILE_OPTION` set to the pinned switch `/std:c++23preview` (or `/std:c++23` once §1's pin carries 14.52), so CMake emits that one switch for C++23 instead of its default `/std:c++latest`, and its compile-feature negotiation (GoogleTest's targets require `cxx_std_17`) is satisfied by the same switch rather than adding a second one (CMake "cmake-compile-features"), the warning and conformance flags `/W4 /WX /permissive- /utf-8 /Zc:__cplusplus /Zc:preprocessor /EHsc /external:anglebrackets /external:W0`, the static runtime through `CMAKE_MSVC_RUNTIME_LIBRARY` `MultiThreaded$<$<CONFIG:Debug>:Debug>`, full PDBs in Release (`/Zi`, `/DEBUG:FULL`, `/OPT:REF`, `/OPT:ICF`), `/guard:cf` on every architecture and `/CETCOMPAT` on x64 only (Microsoft Learn documents it for x64 alone), `CMAKE_EXPORT_COMPILE_COMMANDS` on, and `enable_testing()`.
