# TODO-23 -- Imago Video, Timeline, Audio, and Frame Animation

> **Goal:** After its first release Imago edits motion the way Photoshop, Affinity, and GIMP users expect, on the suite media stack instead of a private one: video files open as video layers whose altered frames are stored non-destructively beside a link to the untouched source, a Timeline panel arranges video, image, and audio tracks with keyframes, transitions, and comments, Render Video encodes through the shared encoder, a frame animation panel with onion skin and tweening builds GIF-style animations from layers, the animated formats (GIF, APNG, animated WebP, MNG, FLI and FLC) are authored with their frame options, and GIMP's animation filters and temporal blur generate frames. The operator promoted this work from the backlog on 2026-09-27 because they worried "features will be left behind" (B-043 video and audio, B-044 animation, deferred to after the first release on 2026-09-26). Decoding, playback, audio, and encoding are the suite media stack's (`D01 T11 §1` to `D01 T11 §4`), so Imago owns only its document model, panels, and commands; a source media file is never written, and every save goes through Imago's atomic document writer.

> [!IMPORTANT]
> **Current state (verified 2026-09-27):** Imago has no video, timeline, or animation code: its layer kinds are raster, adjustment, group, text, shape, and smart object (`src/Imago/src/Imago.Core/Layers/LayerType.cs`), and nothing under `src/Imago/` mentions a video layer, a timeline, an animation frame, or onion skin. The suite media stack this file consumes (`D01 T11 §1` to `D01 T11 §4`) is planned, not built: there is no `src/Photon.Core/`, and no Vortice package is referenced by the solution. Animated GIF and animated WebP authoring were explicitly left out of the codec sections (`D03 T17 §8` writes single-frame GIF, `D03 T17 §5` writes still WebP), and Save for Web (`D03 T18 §2`) has no animation controls. Paths below name the targets after the `D03 T01 §1` rename (`Photon.Imago.*`).

## Outcome

- A video file opens as a document with a video layer, and File, Place or Layer, Video Layers, New Video Layer from File adds one; the source file is never opened for writing, and altered frames persist in the `.imago` document.
- The Timeline panel plays video, image, and audio tracks in sync, splits, trims, speeds up, transitions, keyframes, and comments, each edit one undo step.
- Render Video writes an MP4, WMV, or image sequence that decodes back with the exact frame count and within the stated PSNR.
- The frame animation panel builds, tweens, reverses, and plays frames with onion skin, and frames survive save and reopen.
- Animated GIF, APNG, animated WebP, MNG, and FLI and FLC files are written with their frame options and read back frame for frame against ImageMagick 7.1, `apngdis`, and `anim_dump`.
- GIMP's Blend, Burn-In, Rippling, Spinning Globe, Waves, and temporal blur produce frames within tolerance of GIMP 3.2.6's own output.

## 1. Video Layers and Opening Video

Photoshop users retouch video frame by frame: a video file becomes a video layer whose frames are painted, cloned, and filtered while the footage itself stays untouched. Imago adds a video layer kind that links a `D01 T11 §1` media source and stores only the frames the user altered, as per-frame overlays in the `.imago` document, so the source is never written and Restore Frame is exact. The Clone Source panel gains frame offset and lock frame, and the Blur Gallery runs per frame as a smart filter on video layers.
