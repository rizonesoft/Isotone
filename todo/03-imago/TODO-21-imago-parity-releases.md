# TODO-21 -- Imago Parity Releases: 0.2.0 to 1.0.0

> **Goal:** Each Imago parity phase ends with a published, independently installable Imago release on its own `imago-v*` tag, proven on a clean machine, whose release notes list the parity catalog features the phase completed, so progress is shipped rather than accumulated; `imago-v1.0.0` at the end of Phase 27 declares the catalog complete (every `plan` row stamped, every other row carrying its recorded status).

> [!IMPORTANT]
> **Current state (verified 2026-09-26):** Imago's only planned release so far is 0.1.0 (`D03 T06 §3`, `todo/03-imago/TODO-06-imago-release.md`), which has not shipped: no `imago-v*` tag exists and `CHANGELOG.md` has no Imago release section. The release checklist every section here runs is `standards/release.md`. The Imago installer script `installer/Imago.iss` already registers the opt-in `.psd` association (seven `.psd` mentions) that the parity formats extend. The catalog the releases reconcile exists at `docs/parity/imago-parity.md` (2,385 features since the 18 rows routed from the Lumen catalog were added on 2026-09-27, 2,024 of them planned after the operator's 2026-09-27 promotions), but the query every release quotes does not exist until `D00 T01 §6` and `D00 T01 §7` ship it: `scripts/todo-parity.py` is absent. The Imago user guide folder `docs/user/imago/` does not exist yet; `D06 T01 §2` creates it.

## Outcome

- Twelve published GitHub releases, `imago-v0.2.0` to `imago-v1.0.0`, each with an installer, a portable ZIP, and `SHA256SUMS` that match the downloads, and each proven on a clean Windows 11 machine with no .NET SDK.
- At each tag, every catalog row planned to that phase resolves to a stamped section, or was rerouted in the catalog with its reason in the release commit.
- Each release's `CHANGELOG.md` section names the `IP-` ranges it shipped by catalog area, and the Imago user guide has a page for every surface the phase added.
- A document saved by each release opens in the previous release with its new live content degraded to the rendered PNG fallback, never lost.
- No tag moves another app's version: each `imago-v*` release commit carries only its own tag.
- `imago-v1.0.0` carries the parity query's evidence that zero planned rows remain unshipped across Phases 16 to 27, and the README states parity with Photoshop 27.10, Affinity 3.3, and GIMP 3.2.6.

**Adjacency:** list=not-applicable (releases are listed by GitHub Releases, not by a surface this file builds); document=applicable @ D03 T21 §1; settings=not-applicable (no settings of its own); reporting=applicable @ D00 T01 §7; notifications=not-applicable (no runtime surface); permissions=not-applicable (the app writes no files for a release); audit=applicable @ D03 T21 §1; exchange=not-applicable (no formats of its own; each release re-proves the contract of D03 T08 §1 on the installed build); reverse=applicable @ D03 T21 §1

**Adjacency rationale:** The release notes in `CHANGELOG.md` and the user-guide pages are the documents each release carries. Each release quotes the per-phase parity report that `D00 T01 §7` builds. The tag, the release notes, and the stamped rows are the audit trail of what each version shipped. The reverse of a release is the gate itself: a failed clean-machine install or an unreconciled catalog row blocks the tag, and the previous release stays current; a bad release is superseded by the next patch tag, never deleted.

## 1. Imago 0.2.0 (Phase 16)

`imago-v0.2.0` releases Phase 16 (document, canvas, view, history, and layers), so the phase's parity work reaches users as an installable release rather than accumulating on `main`. It follows the checklist in `standards/release.md` exactly, as `D03 T06 §3` did for 0.1.0, quoting each line's evidence, and it adds three parity duties: the phase's catalog rows in `docs/parity/imago-parity.md` are reconciled against their sections' stamps with `query parity --catalog imago` (from `D00 T01 §7`), no Imago menu item is disabled without naming a planned section or a backlog id (the audit `D03 T06 §2` established), and a document saved by this release is opened in the previous release, `imago-v0.1.0` (`D03 T06 §3`), to prove its new live content degrades to the rendered PNG fallback of the `D03 T08 §1` contract instead of being lost. A catalog row that cannot ship is rerouted in `docs/parity/imago-parity.md` in this commit (to a later section, or to the backlog through `add-todo`) with its reason, never left planned and unshipped. The clean machine is Windows 11 (the supported OS); a Windows 10 22H2 smoke is best-effort and recorded, never blocking. No other app's version moves with this tag (`standards/release.md`). The admission clause is the acceptance-bar aim "Imago covers every Photoshop, Affinity Photo, and GIMP capability in its parity catalog", which names each release as the reconciliation of its phase. The release owns no catalog rows of its own: it reconciles the rows of the areas Documents and canvas; View, guides, and measurement; History, clipboard, and the Image menu; Layers and the Layers panel; Masks, clipping, and blending.

**Fidelity:** no surface of its own (the release artifacts are the installer, the portable ZIP, the release notes, and the tag; each surface was captured by the section that built it).

**Needs:** Clean Windows machine (no .NET SDK)

**Requires:** display-session -- launching the installed app on the clean machine and driving each new surface needs an interactive desktop
