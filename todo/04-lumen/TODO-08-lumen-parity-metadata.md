# TODO-08 -- Lumen Parity: Metadata, Keywords, and Places

> **Goal:** Lumen reads, shows, edits, and writes every metadata field Lightroom Classic, ACDSee, and IrfanView handle (EXIF, IPTC Core and Extension, XMP, MWG mappings, comments, and descript.ion captions) with status and conflict tracking. Following the operator's 2026-09-27 decision "Safe by default, opt-in writes", edits land in the catalog and in XMP sidecars by default, and only when the user turns embedding on does Lumen write metadata into the original files (JPEG, TIFF, DNG, and PNG) as ACDSee does, through the suite atomic writer with a verified backup copy; exported and converted copies always carry embedded metadata. The file also delivers the metadata panel and properties pane with every field set and custom views; metadata presets and sync; capture-time editing and batch time stamps; the full keyword toolset; and a map view with an offline basemap, geotagging, saved and private locations, GPX track logs, and offline reverse geocoding (promoting B-034), usable with no network at all. The code lives in `src/Lumen/Photon.Lumen.Core/Metadata/`, `Keywords/`, and `Places/`, and `src/Lumen/Photon.Lumen.Desktop/Metadata/` and `Map/`.

## 9. Embedding metadata into originals, opt-in

ACDSee's "Embed ACDSee Metadata" and Lightroom's "Save Metadata to File" for JPEG, TIFF, and DNG write metadata into the photo file itself, and users who move files between tools expect it. The operator decided on 2026-09-27 ("Safe by default, opt-in writes") that Lumen offers the same as a setting: sidecars stay the default, and when the user turns embedding on, Lumen writes XMP, IPTC, and EXIF into supported originals through the suite atomic writer, after an optional backup copy that is on by default. This changes the frozen original-file guard; the operator's decision is the approval, and this section records it rather than granting it. The guard, the setting `Lumen.Originals.InPlace.EmbedMetadata`, the backup, and the atomic in-place replace are `D04 T11 §1`'s (`OriginalGuard`, `OriginalWritePolicy`, and `InPlaceWriter`, built in Phase 31), so this section adds no second policy, backup copier, or writer. It adds what is specific to metadata: format rewriters that never re-encode pixels (each copies the image data bytes verbatim and replaces only metadata structures), a verifier that refuses any result whose image data or metadata readback differs, the routing from §8's `MetadataWriter`, and the per-format capability list.
